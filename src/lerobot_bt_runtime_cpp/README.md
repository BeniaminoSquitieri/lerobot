# lerobot_bt_runtime_cpp

This ROS 2 package is the C++ BehaviorTree.CPP runtime for the LeRobot BT
stack. It loads generated BT XML, ticks the tree, applies retry/control-flow
semantics, and exposes the custom BT leaves that call the Python skill server.

It does not own task profiles anymore. Task XML and BT parameter YAML are
generated at runtime by `../lerobot_bt_python/bt_generation/` and passed to the
runner explicitly.

This package does not load LeRobot policies and it does not command the robot
directly. Those responsibilities belong to `../lerobot_bt_python` and
`../lerobot`. This package is part of the P0 real robot runtime path; see
[../../docs/robot_runtime_code_map.md](../../docs/robot_runtime_code_map.md).

## Main Files

| Path | Responsibility |
| --- | --- |
| `src/lerobot_bt_main.cpp` | Executable entry point. Requires `tree_xml_path`, loads generated params, registers BT nodes, creates the tree, ticks it, and optionally publishes Groot/Groot2 state. |
| `src/run_named_command_node.cpp` | Base service-backed command node plus `DoSkill`. |
| `src/await_scene_node.cpp` | Scene-gate node that opens/polls VLM checks. |
| `include/lerobot_bt_runtime_cpp/*.hpp` | Public C++ declarations for the runtime nodes. |
| `launch/generated_bt.launch.py` | Generic launch wrapper for a generated XML/YAML pair. |
| `CMakeLists.txt` | Builds `lerobot_bt_runner` and installs headers, executable, and the generated-BT launch wrapper. |

## Relationship With Other Packages

```text
lerobot_bt_python.bt_generation
  -> writes generated_bt/trees/<task>.xml and generated_bt/config/<task>_bt.yaml
  -> lerobot_bt_runtime_cpp loads those generated files
  -> uses lerobot_bt_interfaces service types
  -> calls lerobot_bt_python server over ROS 2
  -> waits for VLM state stored by lerobot_bt_python
```

BehaviorTree.CPP itself is expected from the ROS 2/system environment. See
`../README.md` for setup commands and the package-map dependency note.

## Runtime BT Inputs

The runner expects two generated files:

| Input | Source |
| --- | --- |
| `tree_xml_path` | Generated by `lerobot_bt_python.bt_generation.generate` under `generated_bt/trees/<task>.xml`. |
| ROS params YAML | Generated by the same command under `generated_bt/config/<task>_bt.yaml` and passed as `params_file` in launch or `--params-file` with `ros2 run`. |

Name alignment matters:

1. Generated XML nodes read blackboard keys such as
   `{place_first_toast_skill}`.
2. Generated BT params YAML assigns those keys to concrete names such as
   `place_first_toast`.
3. The matching Python `*_executor.yaml` must list the same robot skill names
   under `expected_skill_names` and `skills`.

## Runner Parameters

- `tree_xml_path`: required generated XML tree to load.
- `bt_command_service`: service used for BT -> Python commands. Default:
  `/lerobot_bt/run`.
- `vlm_state_service`: service used to poll Python VLM state. Default:
  `/lerobot_bt/vlm_state`.
- `tick_ms`: BT tick period. Default: `100`.
- `enable_groot_publisher`: publish tree state for Groot/Groot2. Default:
  `true`.
- `groot_publisher_port`: Groot2 publisher port when supported. Default:
  `1667`.

## Commands

Generate a task first:

```bash
PYTHONPATH=src python -m lerobot_bt_python.bt_generation.generate \
  --task make_sandwich \
  --planner template \
  --registry src/lerobot_bt_python/bt_generation/skills_registry.yaml \
  --executor-yaml src/lerobot_bt_python/make_sandwich_executor.yaml \
  --output-dir generated_bt
```

Launch the generated tree:

```bash
ros2 launch lerobot_bt_runtime_cpp generated_bt.launch.py \
  params_file:=generated_bt/config/make_sandwich_bt.yaml \
  tree_xml_path:=generated_bt/trees/make_sandwich.xml
```

Or run the executable directly:

```bash
ros2 run lerobot_bt_runtime_cpp lerobot_bt_runner \
  --ros-args \
  --params-file generated_bt/config/make_sandwich_bt.yaml \
  -p tree_xml_path:=generated_bt/trees/make_sandwich.xml
```

Build, launch, Groot2, and preflight commands are centralized in
`../README.md`.

## Changing A Task

- Change task order/control flow in
  `../lerobot_bt_python/bt_generation/task_templates.yaml` or the planner path
  that emits Linear IR.
- Change names, timeouts, retry counts, and human/VLM gate metadata in
  `../lerobot_bt_python/bt_generation/skills_registry.yaml`.
- Change policies, robot hardware, processors, camera topics, and skill
  transitions in `../lerobot_bt_python/*_executor.yaml`.
- Regenerate XML/YAML before launching the runner.
- Change service fields only in `../lerobot_bt_interfaces` and update both C++
  and Python users together.
